# Languages (i18n) — 2026-11-03

Owner asks: "Add more languages as well". Brief: `workstreams/briefs/languages-and-final-package-2026-11-03.md`.

## What shipped

- 13 locales: `en`, `es`, `pt-BR`, `fr`, `de`, `zh-CN`, `ja`, `ko`, `tr`, `vi`, `ru`, `hi`, `id`.
- Every user-facing string lives in `web/locales/<code>.js` (`export default { key: text }`). No i18n library.
- Code calls keys only: `t('key')` in `web/app.js`, `L('module.key', {p0: value})` in screen modules,
  `translate(lang, key, args)` from `web/i18n.js`. The 486 literal and 9 template `L(en, es)` pairs, the
  `button(action, en, es)` / `uiError(en, es)` helpers, the programs error table, `lib/trading-errors.mjs`
  Spanish column (web only; the server still uses the English column), the media uploader copy, the app
  chrome ternaries and the 98 server-error regex maps were all moved to keys.
- English (`web/locales/en.js`) is bundled into `dist/app.js` and is the fallback for any key a locale
  lacks. Other locales are static data modules copied to `dist/locales/<code>.js` by `tools/build.mjs` and
  loaded on demand (`loadLocale`), so a visitor downloads only English plus their own language.
- Server errors: `serverError(message, lang)` matches the anchored English patterns and fills `{1}`, `{2}`
  captures into the locale's template. English and unknown messages pass through unchanged.
- Picker: native names (`English`, `Español`, `Português (Brasil)`, `Français`, `Deutsch`, `简体中文`,
  `日本語`, `한국어`, `Türkçe`, `Tiếng Việt`, `Русский`, `हिन्दी`, `Bahasa Indonesia`) from
  `lib/locales.mjs`. The closed control shows a short code (`DE`, `JA`, …) so the header fits 390 px; the
  native `<select>` sits on top of it, so keyboard and screen readers use the real control.
- Choice persists in `localStorage['plugged.language']`; `<html lang>` and `<html dir>` follow it. First
  visit follows `navigator.languages` (exact match, then base language: `pt-PT → pt-BR`, `de-AT → de`;
  `zh-TW/HK/Hant` are not mapped to Simplified Chinese and fall through to the next preference or English).
- Numbers, dates and currency already used `Intl.*` with the active `lang`; the codes are valid BCP 47 tags.
- RTL: `direction(code)` in `web/i18n.js` returns `rtl` for subtags listed in its `RTL` set (empty today).
  Adding Arabic/Hebrew = add the locale file, its code in `lib/locales.mjs`, the subtag in `RTL`, then
  audit CSS for physical `left/right` properties. Out of scope for this build.
- Untranslated on purpose: ETH, CID, bps, tickers, addresses, IPFS, ERC-20, EVM, RPC, USD, V4, Uniswap,
  Robinhood, Carbon, Plugged, Pons, Bags, Wormhole, GitHub, chain id 4663, BAGS_API_KEY, calldata, nonce,
  JSON, PNG, MiB, UTC. `test/i18n.test.mjs` fails if a translation drops one of these that the English
  string contains.

## Adding or changing strings

1. Add the key to `web/locales/en.js` and use it in code.
2. `bun tools/i18n-assemble.mjs dump <file>` writes numbered `n|English` lines. Translate into
   `n|translation` files, then `bun tools/i18n-assemble.mjs build <code> <files…>` rewrites
   `web/locales/<code>.js`, checking placeholders. Or edit the locale file directly.
3. `bun test test/i18n.test.mjs` — every literal key used in `web/*.js` must exist in `en`; locale keys
   must exist in `en`; placeholders and protected tokens must match.

## Known limits

- The file input's "Choose File / No file chosen" text is drawn by the browser in the browser's language,
  not the page language.
- Fixture/test copy ("BROWSER TEST — simulated coin") and on-chain names are data, not UI, and stay as-is.
- Server-side error text that does not match a known pattern is shown in English.
